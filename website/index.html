What the app is for

Practical tools, with clear boundaries

The desktop and mobile clients share a project, not every platform capability. Each feature below identifies its service requirements and what it does not do.

Windows · modem

USSD and GSM workflows

Manage supported USB modem sessions, USSD operations, SMS and network information from Windows. Carrier, modem firmware, SIM, and network availability affect results.

Three clients · relay

Private messaging

Send sealed messages through a configured relay. Recipients need a compatible app identity and reachable relay infrastructure; the apps do not include a public relay service.

Three clients · calling service

Voice, video and group calls

Call other app users through configured signalling and media services. Calls are not available merely by installing the app; relay routing and calling infrastructure must be deployed.

Opt in · tracker service

Device tracking

Pair your own devices, check status, and share a single location only when you request it. Lost mode changes tracker status; it does not lock or remotely control a device.

User-started · AI provider

Assistant panel

Ask questions and use local assistant commands when you choose. AI requests go to the configured provider. The assistant does not get remote shell or unrestricted device-control access.

Configured · not bundled

Relays and linked devices

Relays connect app identities and carry supported traffic. Use trusted endpoints and keep their credentials private. No tracker, relay, media server, or AI quota is supplied by the installer.

Start safely

Three steps to a real test

A download is the client only. These are the minimum pieces to test communication between Windows, Android, and iOS.

1. Install a matching preview

Use the Windows executable and Android debug APK from the same preview release. iOS builds are coming soon and are not included in these downloads.

2. Configure trusted services

Connect compatible clients to a reachable relay with valid TLS identity. Calls also need the configured calling/media service; tracking and AI each require their own endpoint and credentials.

3. Pair and test deliberately

Register each app identity, then test a message and call between devices on different networks. Grant location only for an intentional one-time share. Never publish or reuse pairing secrets.
